### 2.5 트럭·버스 class 뒤집힘 수정

**문제:** 탐지 모델의 class가 바뀔 때 class별 트래커도 달라져 ID 변경과 이력 단절이 잦았다. 작은 박스의 트럭·버스가 다른 종류로 판단되는 모델 오류도 함께 있었다.

**변경 내용 — `c4fc8b6`**

- `car`, `bus`, `tru`, `truck`을 하나의 트래커로 묶었다. 오토바이·자전거는 제외했다.
- 트랙별 class 투표를 적용했다.
  - 점수 감쇠: 0.97
  - class 전환 차이 기준: 2.0
  - 가중치: `min(h/80, 1)^2 × prob`
  - 탐지와 추적 박스 매칭: IoU 0.3 이상
- 변경 파일은 `nc_cnn_tracker.c`이며, `nc_traj`·`nc_cutin` 자체는 수정하지 않았다.

**결과 — 영상 한 번 재생분의 보드 로그**

| 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 0001 전체 class 뒤집힘 | 84회 | 6회 |
| 0001 흰색 소형 트럭 뒤집힘 | 47회 | 1회 |
| 0001 같은 차량의 ID 변경 | 84회 | 1회 |
| 0002 전체 class 뒤집힘 | 10회 | 0회 |
| 0003 전체 class 뒤집힘 | 38회 | 3회 |

**한계 및 기록 정정**

- **class 표시 안정화와 모델 분류 정확도 개선은 다르다.** 멀리 있거나 일부만 검출된 트럭·버스의 첫 class 오류는 남았다.
- 통합 추적으로 ID 변경은 줄었지만, `nc_traj`·`nc_cutin`은 여전히 `(class, track_id)`를 사용한다. 상세 기록에 따르면 **최종 class가 실제로 바뀔 때 해당 이력은 다시 시작**된다. “class가 바뀌어도 모든 예측 이력이 완전히 유지된다”는 표현은 피한다.
- 반복 재생 로그 전체와 시뮬레이션 수치는 최종 성과표에 섞지 않고, 한 번 재생분의 보드 수치를 사용했다.
- 모델 재학습은 필요한 원본 모델·데이터·변환 도구가 없어 보류했다. 후처리 투표만으로 첫 분류 오류까지 해결하지는 못했다.

### 2.8 기본 재생·배포·백업 정리

### 2.9 보드 안정성 조사

| 증상 | 확인 내용 | 결론 |
| --- | --- | --- |
| kdb 크래시 | `rb_erase`·`hrtimer` 관련 스택, 비정상 포인터 관찰 | 타이머 메모리 손상 의심, 근본 원인 미확인 |

- 새 바이너리에서 kdb를 두 번 관찰했지만 표본이 적어 코드 변경 때문이라고 확정할 수 없다.
- 다음 kdb 발생 시 재부팅 전에 타이머 소유자·스택 정보를 확보하는 절차가 상세 기록에 정리돼 있다.
