## 1. 통합하면서 네 코드에 영향 있는 변경 (3개)

### [1-1] `nc_cutin.c` `find_recent()`: 중복 판단을 "같은 추적 번호"로만

바꾸기 전:
```c
if (r->class_id == t->class_id && r->track_id == t->track_id) return r;
if (near_box(t->bx, t->by, t->bw, r->bx, r->by, r->bw)) return r;
```
바꾼 뒤:
```c
if (r->track_id == t->track_id) return r;   // near_box는 __attribute__((unused))로만 남김
```

**이유**
- 준이 최신 트래커(d10b2d4)는 car/bus/truck을 트래커 하나로 추적하고, class는 투표로 정해.
- 그래서 같은 차가 트럭↔승용차로 바뀌어도 번호는 그대로야. 네가 near_box를 넣은 이유("재인식되면 번호가 새로 생김")가 없어진 거지.
- 그런데 near_box가 남아 있으니, 박스 폭 이내에 나란히 있는 다른 차까지 같은 차로 묶었어.

**근거** (px, 차선 그대로, `bev_obj.csv` → 부록 B)
- 같은 프레임에 두 차가 동시에 있어.

  | id | class | x | y | 크기 | 정체 |
  |---|---|---|---|---|---|
  | 2 | car / tru | 1020~1037 | 635~680 | 약 155×115 | 끼어드는 은색 차 |
  | 4 | tru | 903~910 | 582~588 | 약 127×109 | 앞쪽 트럭 |

- id 2는 class가 car→tru→car로 바뀌는데 번호는 2 그대로야.
- 고치기 전 로그: `cut-in ON class:1 id:2 (same vehicle as class:3 id:4, no new trigger)` → 은색 차 녹화가 안 남았어.

**결과:** 고친 뒤 test3 6/6, px 은색 차가 따로 경고·녹화돼. PC 시험 33개 통과.

**주의:** 준이 트래커 기준이라, class별 트래커로 돌아가면 near_box가 다시 필요해.

### [1-2] `nc_traj`에 함수 추가, 끼어들기만 그걸 씀

- 준이 최신 `nc_traj`는 "미래 구간"에 반응이 느린 부드러운 속도 필터(fvx/fvy)를 써.
- 그대로 쓰니까 네 PC 시험 M(옆 차선 차가 빨리 멀어짐)이 FAIL(오경보)이 나.
  - 네 "빨리 멀어지는 차 거르기"는 미래 위치(행)로 판단하는데, 부드러운 필터라 반응이 늦어서 그래.
- 그래서 `nc_traj_get_future_center_fast()`를 추가했어. 미래 구간도 빠른 필터(vx/vy)를 쓰고, 네가 쓰던 예전 nc_traj와 계산이 같아.
- 끼어들기 판단과 끼어들기 경로선은 `_fast`를 쓰고, 미니맵 화살표는 준이 원래 함수 그대로야.

PC 시험 결과 (`test_lanesrc.c`, 우리 통합 코드로 빌드)

| 조합 | 14fps | 30fps | NODROP |
|---|---|---|---|
| 준이 nc_traj 그대로 | M FAIL | M FAIL | M FAIL |
| `_fast` (지금) | PASS | M FAIL | PASS |
| 네가 쓰던 예전 nc_traj | PASS | M FAIL | PASS |

※ 30fps M FAIL은 네 원래 결과랑 같아.

### [1-3] `nc_ldw.c` 병합 (네 11/09 + 준이 미니맵용 함수 + 우리 화면)

- 네 11/05를 기준으로 3-way 병합했어. 충돌 6곳은 둘 다 살렸어.
  - 준이: geom ring, 차선 점 공유 (`ldw_publish_geom`, `nc_ldw_app_get_geom` 등)
  - 너: held/lead/virtual, 앞차, 차선 끊기 시험
- `[TEAM]` 줄은 다 켰어 (지연값, `nc_rec_trigger(0)`, `nc_model_get_mode()==MODE_SKIP` → 실제 서영 함수).
- `cam_offset_m` 기본값은 0이야 (네 auto_center 쓰려고). `LDW_CAM_OFFSET` 환경변수는 그대로야.
- "LDW: no lane (cut-in: held lane)" 문구는 네 것 그대로 두고, 위치만 우리 HUD 3줄째로 옮겼어 (chh-150, 큰 글씨, 그림자, 회색 0.5).
- 확인한 것:
  - `[LDW] camera: ... usual place learned` / `[LDW] ego lane for cut-in: ...` 로그가 나와.
  - 차선 끊기 시험(`LDW_DROP_*`)에서 held→virtual로 전환되고, 끼어들기도 계속 잡혀.

## 2. 남은 문제: px 3.7초 옆 차선 트럭(class 3) 끼어들기 오경보

### 증상

차선이 보일 때(lane measured)도 반복할 때마다 트럭이 먼저 켜져.
```
cut-in ON  class:3 id:4  (candidate 108 ms, 4 frames, lane measured)
cut-in ON  class:1 id:2  (candidate 115 ms, 4 frames, lane measured)   ← 진짜 은색 차
```
- 네 1109 보드 결과(수정후_5개영상)에도 3.73초 `class:3 id:1` → 6.73초 `class:1 id:2 (same vehicle)`가 있었어. 이것도 트럭이었을 가능성이 커.
  - 예전엔 near_box가 둘을 "같은 차"로 묶어서 가려졌던 것 같아.
- 정리하면, 통합 때문에 생긴 문제가 아니라 원래 있던 문제고, [1-1]을 고치면서 드러난 거야.

### 상세 로그
`NC_CUTIN_STATS` 켜고, 차선 그대로 → 부록 A

### 내가 본 원인
- 트럭은 우리 오른쪽 선 바로 바깥에 있어 (u_now 1.15~1.22).
- 다가갈수록 트럭 왼쪽 옆면이 보여.
  - 그래서 박스가 우리 쪽으로 넓어지고(118×113 → 208×190), 박스 바닥 가운데가 실제 차 위치보다 우리 차선 쪽으로 끌려와.
- 1초 뒤 예측은 바닥이 아래(가까운 쪽, 차선이 넓은 행)로 내려가. 그래서 u_fut가 0.83~0.89가 되고 후보가 돼.
- 박스가 크게 튀기 **전** 4프레임(폭 118~121)부터 이미 후보였어. 그래서 박스 급변 한 번만 막아서는 안 잡혀.
- 네 `nc_cutin.h`에 써 둔 "큰 차는 가까워질수록 옆면이 보여 박스 가운데가 끌린다(11/06 버스)"랑 같은 현상으로 보여.
- 참고: 그때 차선 로그상으로는 우리 차가 오른쪽 선에 붙은 것처럼 나와 (dist_r 0 ~ -0.09m).
  - 그런데 옆 속도는 0.1m/s 안팎이라 차선 변경은 아니야.
  - auto_center 학습 전(10초 전)이라, 카메라 오프셋 때문으로 봤어.

### 해본 것 (환경변수, 빌드 없이)

| 시험 | px 트럭 | px 은색 차 | test3 | 비고 |
|---|---|---|---|---|
| 기본 (point=center, margin=0.10) | 켜짐 | 켜짐 | 6/6 | |
| `CUTIN_POINT=2` (config point=both 확인) | 켜짐 | 켜짐 | 6/6 | 옆면이 포함된 박스라 우리 쪽 아래 모서리가 이미 차선 안 |
| `CUTIN_MARGIN=0.15` | 없음 | 없음 | - | 은색 차도 놓침 |
| `CUTIN_MARGIN=0.20` | 없음 | 없음 | 6/6 | 은색 차도 놓침 |

→ 은색 차(천천히 끼어듦)와 트럭은 u_fut 깊이로는 구분이 안 돼.

## 4. 부탁하는 것

1. **트럭 오경보 처리 방법을 정해줘.** 네 PC 시험·기준값이랑 맞춰야 해서 네가 판단하는 게 맞을 것 같아. 내가 생각한 방향은 이 정도야.
   - 도로 좌표(m)로 옆 방향 속도를 구해서, 실제로 우리 쪽으로 움직일 때만 후보로 잡기
   - 옆 차선 차는 옆면이 안 섞이는 먼 쪽 모서리로 판단하기 (단, test3처럼 가까이서 비스듬히 들어오는 차를 놓치는지 확인 필요)
2. **[1-1] 중복 판단 변경이 괜찮은지 봐줘.** 준이 트래커 기준이면 번호만으로 충분하다고 봤어.
3. **고치면 `nc_cutin.c/h`만 주면 내가 합칠게.** nc_traj는 `_fast` 함수를 쓰니까 그대로 둬도 돼.

참고 (급하지 않음): 준이 미니맵은 실제 차선만 그려. 그래서 차선을 잃으면 네 held/virtual 차선이 미니맵엔 안 나와. 준이한테도 따로 말할게.
