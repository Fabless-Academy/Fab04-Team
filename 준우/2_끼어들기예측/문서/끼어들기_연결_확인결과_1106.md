# 끼어들기 예측: 연결·수정·보드 확인 (준우, 11/06)

준이 끼어들기 코드(`nc_cutin`, `nc_traj`)를 내 LDW와 서영 임시 함수에 연결하고, 보드에서 실제 영상으로 확인한 결과야.

## 0. 요약

- 끼어드는 영상 2개에서 **진짜 끼어들기 2건 모두 경고**, 오경보 0건, 녹화 호출은 차 한 대당 1번.
- 준이 판정 방식(지금 박스 아래 가운데는 내 차선 밖 + 예측 위치는 안쪽)은 **그대로**. 값과 켜고 끄는 규칙만 바꿨어.
- 바꾼 값은 보드에서 환경변수로 다시 빌드 없이 바꿀 수 있어 (5장).

## 1. 파일 구분

| 파일 | 출처 | 상태 |
|---|---|---|
| `새파일/.../cnn/core/nc_traj.c, nc_traj.h` | 준이 | **원본 그대로** |
| `새파일/.../cnn/core/nc_cutin.c, nc_cutin.h` | 준이 | **준이 원본 + 준우 수정** (2장, `diff/nc_cutin_준이원본대비.diff`) |
| `새파일/.../cnn/core/nc_class.c, nc_class.h` | 준우 | `nc_traj.c`가 부르는 `nc_class_is_vehicle()`이 없어서 새로 만듦 (TRICHIMERA: car, bus, tru = 1~3) |
| `수정파일/.../nc_cnn_aiware_runtime.c/.h`, yolov8·ufld·pelee·segmentation 후처리 | SDK | timestamp 전달 + `nc_traj_update()` 호출 (`diff/수정파일_SDK원본대비.diff`) |
| `../3_공통/수정파일/.../wayland_npu_app.c, Makefile` | SDK | 끼어들기 연결 부분은 `../3_공통/diff/끼어들기_추가부분.diff` |

## 2. 준이 `nc_cutin`에서 바꾼 것

| 항목 | 준이 원본 | 지금 | 이유 (근거) |
|---|---|---|---|
| 예측 시간 | 500ms | **1000ms** | PC 가상 시험에서 6초에 걸쳐 천천히 들어오는 차를 500ms로는 못 잡음. 1000ms는 잡고 오경보 0 |
| 켜기 | 3프레임 연속 | **100ms 이상 + 최소 3프레임** | 앱이 30fps가 아니라 약 15fps. 프레임 수 기준이면 속도에 따라 동작이 달라짐 |
| 끄기 | 10프레임 | 333ms | 위와 같음 |
| 내 차선변경 후 쉬기 | 15프레임 | 500ms | 위와 같음 |
| **최소 표시** | 없음 (약 0.5초 만에 꺼짐) | **1초** | 차 가운데가 선을 넘으면 바로 후보가 아니게 돼서 경고가 너무 짧았음 |
| **같은 차 중복** | 없음 | **3초 안에 같은 자리면 녹화 다시 안 함** | 같은 차가 트럭→승용차로 다시 인식되면 추적 번호가 새로 생겨 경고·녹화가 두 번 됨 (보드 확인) |
| 먼 차 제외 (`MIN_LANE_W`) | 120px | **200px** (약 17m보다 먼 차) | 옆 차선의 먼 버스에 오경보 1건. 200px로 없어지고 진짜 끼어들기 2건은 그대로 잡힘 |
| 차선 결과 나이 | 200ms 고정 | **200ms와 3프레임 간격 중 긴 쪽** | 그리기 순서상 끼어들기는 한 프레임 전 차선을 씀. 느린 화면에서 차선이 전부 버려졌음 |
| 판정 통계 `no_lane` | 하나로 셈 | **far / lost / stale + fps로 나눔** | 원인을 바로 알 수 있게 |
| 판정 통계·후보 로그 | `NC_CUTIN_STATS` 꺼짐 | 꺼짐 (시험할 때만 켬) | 켜면 후보마다 u값·박스·차선 위치도 찍힘 |

시험만 하고 **기본으로 안 쓰는 것**: `CUTIN_POINT` (판정 기준점)
- 1 = 안쪽 아래 모서리: 버스 오경보는 없앴지만, 가까이서 들어오는 차를 놓침 (처음 보일 때 이미 모서리가 내 차선 안)
- 2 = 가운데 + 모서리: 시험 영상에서는 가운데 기준과 결과가 같았음
- 기본은 0 = 가운데 (준이 원본)

## 3. 내가 만든 연결 부분 (준이 work 저장소와 겹침)

| 위치 | 내용 |
|---|---|
| `nc_cnn_aiware_runtime.h/.c` | `cnn_output_info.time_stamp_us` 추가, `run_cnn_program()`에서 값 넣기 |
| yolov8·ufld·pelee·segmentation 후처리 | `time_stamp = 0` → `cnn_output->time_stamp_us` |
| `nc_cnn_yolov8_postprocess.c` | `nc_cnn_track()` 바로 뒤 `nc_traj_update()` |
| `wayland_npu_app.c` | 프레임 꺼낸 시각 `nc_get_mono_us_time()` → `g_disp_frame_ts_us[]`, 그리기 전 `nc_traj_predict_frame()`, ByteTrack `net_id = NETWORK_TRI_CHIMERA`, DETECTION 분기는 준이 snippet 그대로 + `nc_rec_trigger(1)` |
| `Makefile` | `USE_BYTETRACK = yes`, `nc_class.c`, `nc_traj.c`, `nc_cutin.c` |

## 4. 보드 확인 결과 (최종 버전)

| 영상 | 실제 장면 | 결과 |
|---|---|---|
| `test3_1080p.mkv` (국내 블랙박스, 8.6초) | 흰 차가 가까이서 끼어듦 (0~1.3초) | ✅ 반복 재생마다 1.2~1.4초에 경고, 1초 표시 |
| `px_5915075.mp4` (Pexels, 27.5초) | 은색 차가 천천히 끼어듦 (3~7초) | ✅ 3.7초 경고, 트럭→승용차로 다시 인식돼도 녹화 1번 |
| 같은 영상 9초 | 옆 차선 먼 버스 | ✅ 경고 없음 (전에는 오경보) |
| `1920_1080_0001.mp4` (기본) | 끼어들기 없음 | ✅ 경고 0 |

- 앱 속도 약 15fps, 종료·재실행 정상, weston 유지.
- GPU(Mali) 오류는 실행마다 0~5건 (화면 영향 없음, 원인 미확인).
- 영상은 용량이 커서 GitHub엔 안 올렸어 → Google Drive. 휴대폰 영상(.mov, HEVC)은 보드가 제 속도로 못 풀어서 보드에서 mpeg2로 변환해서 씀:
  ```sh
  LD_LIBRARY_PATH=$PWD/misc/lib misc/ffmpeg -i in.mov -vf "crop=2080:1170,scale=1920:1080" -r 15 -an -c:v mpeg2video -q:v 3 out.mkv
  ```

## 5. 보드에서 값 바꾸기 (다시 빌드 필요 없음)

```sh
CUTIN_MIN_LANE_W=150 ./run_app_wayland_npu.sh misc/image_npu/px/px_5915075.mp4
```

| 환경변수 | 기본 | 의미 |
|---|---|---|
| `CUTIN_HORIZON_MS` | 1000 | 예측 시간 |
| `CUTIN_MARGIN` | 0.10 | 예측 위치가 차선 안쪽으로 들어와야 하는 정도 (차선 폭 비율) |
| `CUTIN_ON_MS` / `CUTIN_OFF_MS` | 100 / 333 | 켜기 / 끄기 |
| `CUTIN_MIN_ON_MS` | 1000 | 최소 표시 |
| `CUTIN_DUP_MS` | 3000 | 같은 차로 보는 시간 |
| `CUTIN_MIN_LANE_W` | 200 | 먼 차 제외 기준 (px) |
| `CUTIN_LANE_STALE_MS` | 200 | 차선 결과 나이 최소 기준 |
| `CUTIN_LC_HOLD_MS` | 500 | 내 차선변경 후 쉬는 시간 |
| `CUTIN_POINT` | 0 | 0 가운데 / 1 모서리 / 2 둘 다 |

앱 시작할 때 `[nc_cutin] config: ...` 로그에 적용된 값이 나와.
