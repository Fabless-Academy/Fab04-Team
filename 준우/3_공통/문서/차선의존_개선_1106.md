## 1. 내 차선 출처

`nc_ldw.c`가 끼어들기에 차선을 줄 때 **어디서 나온 차선인지**를 같이 줘. 위에서부터 먼저 씀.

| 출처 | 언제 | 끼어들기 규칙 |
|---|---|---|
| `detected` / `one-side` | 선이 보임 (0.2초 안) | 보통 |
| `held` | 선이 0.2~**1.0초** 안 보임 | 보통 |
| `lead` | 그 뒤, 앞차가 1초 이상 보이면 | 보통 + **들어오는 움직임 규칙** |
| `virtual` | 그 뒤, 앞차가 없으면 | 보통 + **들어오는 움직임 규칙** |
| `none` | 도로 모양을 한 번도 못 배움 | 판단 안 함 |

- 원래 함수 `nc_ldw_get_ego_lane()`은 지금도 **실제 선만** 줘. 다른 사람이 쓰던 동작은 그대로야.
- 끼어들기는 새 함수 `nc_ldw_get_ego_lane_src()`를 써.
- 로그:
  - `[LDW] ch0 ego lane source: held -> virtual (y=864: 701-1228 px, last measured 687-1248, ...)`
  - `cut-in ON ... lane virtual`

## 2. held / virtual

**held (잠깐 유지)**
- 마지막 차선을 내 차가 옆으로 움직인 만큼 옮겨서 써.
- 보드에서 1초 넘은 held 차선이 차선 폭의 10%쯤 틀어져 오경보가 나서 바꿨어:
  - 유지 시간 **1.5 → 1.0초**
  - 옆 속도는 0.2m/s 넘는 부분만 반영 (속도 추정이 흔들려서)

**virtual (가상 차선)**
- 선이 보일 때 배워둔 값으로 만들어: 줄마다 차선 폭, 소실점, 평소 내 차 위치 (약 7초 평균).
- 그 값으로 폭 3.5m 통로를 그려. 화면에는 하늘색 선으로 표시돼.

## 3. 4단계: 앞차 기준 차선 (`lead`)

**생각:** 내 앞에서 같이 가는 차는 내 차선 안에 있어.
- 선이 보일 때 그 차가 **차선 안 어디쯤**에 있는지, **차선 폭의 몇 배 너비**인지 배워둬.
- 선이 사라지면 지금 그 차 위치로 차선을 다시 만들어.
- 평균값인 가상 차선보다 **지금 도로**를 더 잘 따라가 (굽은 길, 내 위치, 도로 모양 변화).

| 단계 | 규칙 |
|---|---|
| 고르기 | 차선이 350px 이상인 줄(가까운 차)에서, 차선 안 u 0.25~0.75 (선이 없을 땐 0.4~0.6만), **끼어들기 경고·후보인 차는 제외**, 가장 가까운 차 |
| 배우기 | 선이 보일 때만: 차선 가운데에서 떨어진 거리(m), 차 폭 ÷ 차선 폭. 5번 이상 배운 뒤에 씀 |
| 믿을 수 있나 | 차 폭 ÷ 차선 폭이 0.35~0.65(1.2~2.3m)여야 배운 값을 씀. 만든 차선 폭이 배운 폭의 0.75~1.3배 밖이면 안 씀 |
| 못 배웠을 때 | 차종 폭(승용 1.8m, 버스·트럭 2.5m)으로 **폭만** 고치고, 가운데는 가상 차선 그대로 |
| 버리기 | 0.5초 넘게 안 보임 / 박스 폭이 한 번에 30% 넘게 바뀜 / 선이 없을 때 가상 차선 기준 u 0.1~0.9를 벗어남 (앞차가 차선 바꿈) |
| 사용 | 1초 이상 따라간 뒤, held 다음·virtual 앞 순서 |

- 차 정보는 `nc_cutin_eval()` 안에서 `nc_ldw_feed_vehicle()`로 넘겨. **`wayland_npu_app.c`는 안 건드림.**
- 로그 예:
  - `lead car class:1 id:9 picked (measured lane, bottom 1115,872)`
  - `... learned (offset +0.90m, width 0.55 of lane)`
  - `... left our lane (u 0.90)`

**보드에서 처음 나온 문제와 고친 것**
- 멀리 있는 차(박스 86px)를 앞차로 골라서 차선이 40% 틀렸어. 그래서 고르는 거리를 150px → **350px 이상인 줄**로 줄였어.
- 이상한 배운 값(차 폭이 차선의 0.74배)으로 차선이 좁아져서 오경보 1건이 났어. 그래서 **0.35~0.65 확인**을 넣었어.

**7-2 (차 흐름으로 차선 찾기)는 아직 안 함.** 정체 영상을 구한 뒤 앞차 기준 결과를 보고 정하는 게 좋아.

## 4. 들어오는 움직임 규칙 (`lead`·`virtual`에서만)

- 문제: 가상 차선은 차의 줄에서 실제보다 폭이 10%쯤 틀릴 수 있어 (test3: 가상 1214px, 실제 1079px). 그러면 선 바로 위에서 들어오는 가까운 차가 이미 "안"으로 보여서 후보가 안 돼.
- 추가 규칙: 차 아래 가운데가 **차선 옆에서 0.15 안**에 있고, 1초 뒤 예측이 **가운데 쪽으로 0.25 이상** 움직여 안쪽으로 들어오면 후보.
- 실제 선이 보일 때 규칙은 그대로야.

## 5. 같이 고친 문제

| 문제 | 원인 | 고침 |
|---|---|---|
| 가까워지며 끼어드는 차를 놓침 (**차선이 보여도**, 전 코드부터) | 1초 뒤 바퀴 위치를 지금 박스 높이로 계산 → 실제보다 먼 줄에서 판단 | 트랙마다 박스 높이가 커지는 속도를 재서 1초 뒤 높이로 계산 |
| 같은 차가 1.5초 뒤 다시 켜지면 녹화 2번 | 중복 확인이 "다른 추적 번호"만 봤음 | 같은 번호가 3초 안에 다시 켜져도 같은 차로 봄 |
| 가상 차선에서 경고가 3초 늦음 (px) | 켜기 200ms + 트럭↔승용차 인식이 바뀌며 후보가 끊김 | 켜기 **100ms**(보통과 같음). 보드 오경보 0 확인 |

## 6. PC 가상 시험 (`share/pc_test/test_lanesrc.c`)

| 묶음 | 시나리오 | 결과 |
|---|---|---|
| 차선 보임 | 천천히/빠르게/가까워지며 끼어듦, 옆 차선 유지 | 모두 ○ |
| 1초 끊김 (held) | 빠르게 끼어듦, 옆 차선 유지 | ○ |
| 계속 없음 (virtual) | 끼어듦 3종 + 경고 없어야 하는 8종 (옆 차선, 치우침 0.9m, 흔들림, 앞차, 추월) | 모두 ○ |
| 도로 모양 12% 변함 + 앞차 없음/있음 | 가까이 빠르게, 천천히 끼어듦 / 옆 차선 흔들림 / 차선 안 1.1m / **내 차 0.8m 치우침** | 모두 ○ |
| 앞차가 옆 차선으로 나감 | 옆 차선 차 유지 | ○ (앞차 버림) |

- 10·14·30fps 통과.
- **7fps에서는 3개 놓침** (가까워지며 끼어듦 2개, 앞차 있을 때 천천히 1개): 차 가운데가 선을 넘기 전에 후보가 2프레임뿐이라 "최소 3프레임"에 걸려. 보드는 약 15fps라 해당 없음.

빌드 (PC):
```bash
cd share/pc_test   # fake/ 헤더, stub 파일 같이 있음
R=~/apache6-sr-linux_som_micro/applications; M=$R/common/nc_app_modules
gcc -O1 -DUSE_LDW -I fake -I $M/ldw -I $M/cnn/core -I $M/cnn -I $R/wayland_npu_app \
  $(find $M/cnn/networks -type d | sed 's/^/-I /') -Wl,--wrap=clock_gettime -o t_lanesrc \
  test_lanesrc.c $M/ldw/nc_ldw.c $M/cnn/core/nc_traj.c $M/cnn/core/nc_cutin.c $M/cnn/core/nc_class.c \
  stubs.c netid_stub.c model_stub.c -lm -lpthread
./t_lanesrc ; SIM_FPS=30 ./t_lanesrc ; NODROP=1 ./t_lanesrc
```

## 7. 보드에서 다시 확인하기

새 빌드는 보드와 `output/user_data/applications/`에 있어. 보드의 전 파일은 `app_wayland_npu.before_lanesrc`로 남겨뒀어.

```sh
cd /mnt/user_data/applications
./ldw_board_check.sh 30 misc/image_npu/test3_1080p.mkv                            # 차선 그대로
LDW_DROP_AFTER_S=0.5 ./ldw_board_check.sh 30 misc/image_npu/test3_1080p.mkv       # 차선 없음 → virtual
LDW_DROP_AFTER_S=1 ./ldw_board_check.sh 60 misc/image_npu/px/px_5915075.mp4       # held, virtual
LDW_DROP_AFTER_S=0.5 LDW_DROP_EVERY_S=3 LDW_DROP_LEN_S=1 ./ldw_board_check.sh 30 misc/image_npu/test3_1080p.mkv  # lead
LDW_DROP_AFTER_S=1 ./ldw_board_check.sh 40                                         # 오경보 0이어야 함
CUTIN_LANE_SRC=0 LDW_DROP_AFTER_S=1 ./ldw_board_check.sh 32 misc/image_npu/px/px_5915075.mp4  # 예전 동작 비교
```

결과 파일 cut-in 항목에 `ego lane source changes`, `cut-in ON by lane: measured / held / virtual` 줄이 있어.

| 환경변수 | 기본 | 의미 |
|---|---|---|
| `LDW_EGO_HOLD_S` | 1.0 | held 유지 시간 |
| `LDW_EGO_LEAD` / `LDW_LEAD_MIN_S` | 1 / 1.0 | 앞차 기준 차선 쓰기 / 따라가야 하는 시간 |
| `LDW_EGO_VIRTUAL` | 1 | 가상 차선 쓰기 |
| `LDW_DROP_AFTER_S` / `_EVERY_S` / `_LEN_S` | 끔 | **시험용** 차선 끊기 |
| `CUTIN_LANE_SRC` | 3 | 0 실제만 / 1 +held / 2 +lead / 3 +virtual |
| `CUTIN_LEAD_ON_MS` / `CUTIN_VIRT_ON_MS` | 100 / 100 | 켜기 시간 |
| `CUTIN_VIRT_MARGIN` | 0.10 | 가상 차선 예측 여유 |
| `CUTIN_EST_EDGE` / `CUTIN_EST_MOVE` | 0.15 / 0.25 | 들어오는 움직임 규칙 |
